# DLSS 神经渲染实验工具

## 入口与边界

工具首页在游戏资料库下方提供“DLSS 神经渲染（实验）→ 配置”。这是源码版实验配置入口，
不是经过《异环》实机验证的 DLSS 5 开关。文件配置完成只显示已配置、需进入游戏实测，
不推断 GPU 支持、效果生效、帧率收益或与同步、战报、HUD 的运行兼容性。

它复用[ReShade 代理共存](../roadmap/reshade-compatibility.md)的配置规则；已有 ReShade 用户
与本工具首次准备 ReShade 最终使用同一串联入口，不引入另一套宿主或独立 Loader。

## 用户操作

1. 在设置中确认 `HTGame.exe`，使用已确认且未暂停的中风险或开发模式，并先部署 Calc 原生组件。
2. 打开实验工具，点击“打开组件目录”，通过 ReShade 官网和 RenoDX 作者下载频道获取材料，
   放入默认的数据根 `user-components/neural-rendering/`；也可选择其他文件夹。源码及本地数据根
   位于程序目录时，此目录就在程序目录下；外部数据根布局保留在稳定可写的数据位置，避免平台更新清空。
   已核对的 ReShade Add-on 安装包和神经渲染运行库 ZIP 可直接放入，工具只读取确切内部成员，
   不执行安装器或展开其他文件；已解压的组件同样可用。
   首版界面列出固定实验方案，只接受 `neural_profile.py` 冻结的候选文件哈希；未知或其他版本会显示缺项/冲突。
   不自动下载、捆绑第三方组件，也不安装或升级显卡驱动。
3. “检测”只读取组件、显卡驱动、游戏状态和本机事务记录；不启动游戏、不录制战报、不修改文件。
4. 游戏完全退出后点击“配置实验组件”，查看更改清单并确认。输入字节、原文件哈希、账号/模式
   代次和游戏路径在确认前冻结；确认后不换用所选目录里后来更新的文件。
5. 配置完成后，用户进入游戏，在 ReShade Add-ons 中启用插件的神经渲染功能，再验证画面、
   同步、战报和 HUD。该页面不遥控游戏内的实时开关。
6. “恢复本次配置”恢复此次替换的原文件并移除此次新增文件；已被玩家或更新器改变的 DLL
   保留并报冲突。ReShade 在游戏内保存的新偏好保留，只撤销本方代理引用。

## 文件与生命周期

只处理正式游戏目录的 `d3d12.dll`、`nte-calc-host.dll`、`ReShade.ini`、
`renodx-dlss.addon64`，以及已核实原生 DLSS 目录中的 `nvngx_dlssnr.dll`。
游戏原 `nvngx_dlss.dll`、`nvngx_dlssd.dll`、帧生成与 Streamline 文件不替换。
另一套 RenoDX DLSS 插件、额外 Bridge/Feeder、自定义配置根或 AddonPath、未知代理及目录链接均不自动接管。
玩家不需要手写 INI 或选择串联链路；游戏内渲染参数先使用该版本默认值，实测后再决定是否固化预设。

配置/恢复持有共享原生维护租约，暂停同步及性能 owner，排空连接后再写文件；收尾更新本方部署记录，
自动维护和清理沿用正式组件身份。检测、读取计划和提交使用页面 worker，耗时哈希及复制不在 UI 线程执行。
关闭/账号切换撤销后续写权限，已有写入保留恢复日志，物理线程收尾前不销毁 owner。

本机事务归 `config/neural-rendering/`，按游戏路径身份隔离。日志在第一份游戏文件写入前原子保存，
只含有限目标、前后哈希与专用恢复副本；不含账号数据或第三方登录凭据。中断恢复根据实际字节判定
哪些操作已经发生，不依赖内存中的完成计数，也不重发未知游戏指令。恢复先验证全部目标和副本，
再执行精确文件操作；路径、许可、游戏状态或内容发生变化时停止。

## 验证范围

文件事务、冻结输入、恢复冲突和权限代次专项，以及工具页离屏导航、检测和取消行为已验证。
三主题已做离屏渲染检查；这不替代真实 Windows 混合 DPI 与游戏验收。
真实游戏项目、候选来源与未完成门禁见[神经渲染路线图](../roadmap/dlss-neural-rendering.md)。
