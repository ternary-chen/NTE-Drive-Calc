# 仓库智能推荐

入口为仓库「管理 → 规则处理 → 生成智能规则」。绿色按钮直接读取正式套装与形状目录，将生成规则加入当前列表草稿，可编辑、启停、复制、删除；不再打开角色选择弹窗。已有评级设置时直接沿用；首次未设置过评级时，以可取消的后台任务读取冻结库存，批量评分并按蓝图数量抽样，不执行装备分配。
推荐默认评估全部可计算角色，以及当前配置下各角色全部合法蓝图；按正式角色身份固定排序，同时检查反向顺序和逐角色独立方案。不以是否装备、是否勾选或当前评分高低排除角色。

「保存」仅持久化当前账号的规则；取消窗口丢弃未保存草稿。「保存并计算建议」先保存，再使用相同设置计算冻结仓库。保存后显示简洁计算进度，完成后直接显示建议列表；失败后的重试直接计算。
规则处理页顶部并排编辑「目标保留总量（空幕＋驱动）」与「驱动保留评级」，分别与未来用途储备、驱动评级保护规则共享同一草稿字段，0 表示不限。
只有对应动态规则恰有一条启用时才可编辑；缺失、关闭或启用冲突时置灰并提示未启用对应规则。选择不额外保留会关闭评级规则，可在列表重新启用。
顶部与规则编辑器双向同步，直接修改并保存计算即可，不必重新生成。重新生成沿用可确定归属的总量及评级值，其余智能规则仍整体替换；人工规则保持不变。首次建议以保留总量为准，从宽到严选择规则估算能满足预算的最低评级；先用评级覆盖量和已有锁定、装备及明确保留下限排除超预算档位，剩余档位复用纯规则筛选，不执行配装搜索。正式推荐仍须进行全角色损失检查和按需补回，必要保护超额时明确说明，不解除保护。
总量不限时参考驱动样本评级；缺有效样本时明确使用默认 SSS。用户已有规则、关闭选择或历史评级优先，不因仓库变化自动改值。最后使用的评级只用于再次生成草稿，不额外参与规则计算。
纯手动规则没有上述动态策略时，这两个控件不参与计算，也不会隐式加入保留或弃置动作；原有手动规则执行入口保持原语义。
预览区支持按建议类型和关键词筛选，逐件取消采用。点击「采用勾选建议」把结果放入仓库待保存列表；
最后点击仓库「保存」并确认，才沿用正式状态计划、派发与后验确认流程。生成、保存规则和采用建议都不会直接发出游戏指令。
已有手动草稿与建议目标冲突时不覆盖；数据不足或整批校验失败时不产生可采用的弃置结果。

建议预览复用仓库虚拟卡片，默认查看本次新增弃置，按冻结最高适配评分的得分率降序排列；得分率为评分 ÷（格数 × 10），
空幕面积相同，排序与原始评分一致，驱动因此可跨格数比较。评分和评级由同次公共 Rust 评分提供，缺失显示未评估。
可筛选空幕／驱动、全部弃置、原已弃置或其他建议，排序框可切换得分率升降序，未评估项始终放末尾。
弃置依据区分同类品质和副属性不差、同用途评分候选和未来储备预算取舍；不宣称任意角色收益都被替代。
选中装备可查看同次冻结结果里仍保留的同用途候选；每次打开比较按本次实际勾选目标筛选，状态未知或最终仍带弃置标记的装备不进入候选，原已弃置项须采用恢复建议才可进入。
候选先列同类品质及副属性全面不差者，再列存在属性取舍者；组内统一按被检查装备的最高适配角色评分降序，不混用各件装备自己的最高分。此排序不宣称所有机制下实际伤害都更高。
比较窗口逐项列出属性增减；暴击率与暴击伤害不可仅因同分或高分而视为等价。整批复算证明配装可行及评分不降，不证明每件替换后的实际伤害不降。
全部可采用建议默认勾选，包括当前筛选隐藏的锁定、弃置与恢复正常；不可采用项不参与勾选，用户可逐件取消或批量取消当前显示项。
卡片沿用仓库装备图、名称、主副属性展示，右上头像明确标注「适配」，不表示已装备；其下显示同一最佳适配角色的评级和得分率。卡片底部显示建议及八字以内的弃置依据摘要。
点卡片或点击「查看完整原因与候选」打开公共左右比较弹窗，左侧为检查装备，右侧为选中的保留候选，下方列出完整原因与其他候选。
比较两侧的得分率、评级统一使用检查装备的适配角色，词条差异沿用公共高亮；中间按「↑ 提升」「↓ 降低」分组逐项显示带符号的数值，未知评分保持未评估。
词条名称沿用公共权重色阶，外层取本件最佳适配角色，比较两侧及候选统一取当前比较角色；主副属性分别读取同次公共评分器的冻结权重。悬停可查看权重数值，未知保持原色；背景红绿仅表示属性增减，与权重颜色分开。
完整原因默认折叠为一行入口，展开区域限制高度并独立滚动，为候选列表保留空间。此模式没有装备替换操作，弹窗「采用本件建议」与外层勾选同步。
建议卡片、左右比较及候选卡片的主属性均由本次冻结静态库的公共满级曲线投影，列表顶部和比较弹窗统一说明，不在每张卡片重复标注；悬停保留真实等级。品质和格数分别计算，副属性与真实等级保留原始事实。缺少满级或曲线证据时保留原值及原等级展示，不修改评分、建议结果或账号库存。
卡片勾选框只切换采用，空格执行同一动作，回车打开比较；完整原因仍支持关键词搜索。
排序、筛选均按装备身份保持勾选，筛选隐藏不自动取消勾选；界面显示包含隐藏项的勾选动作总数。

规则保存在账号管理配置中，不新增账号 schema。规则来源记录生成键、版本和初始内容摘要；编辑不改变智能来源。
重新生成等价于先移除全部智能来源规则，再追加本次生成结果；已编辑、已禁用、已删除的智能规则均不阻止重新生成，旧删除记录不再使用。
人工新增规则保持内容及相对顺序；复制规则成为人工副本，动态策略副本默认关闭，同种动态策略同时只能启用一条。
规则页底部「清空智能规则」只移除当前草稿中的智能来源规则，不触发生成、计算或游戏操作；保存后持久化，取消窗口则丢弃清空操作。
词条规则复用现有编辑器；动态规则展示原算法依据，可编辑名称、动作、候选数量或保留评级。残虹光套适配显式列为可关闭规则；关闭后沿用账号套装匹配，不保留隐藏适配例外。
默认规则使用公共推荐内核，分别保存全角色空幕、全角色驱动、未来用途、评级与冗余判定策略；已保存评级不随仓库分变化自动调整，也不把某次装备 UID 名单保存成永久规则。
该功能尚未正式发行，试验版未保存规则的推荐参数需重新生成；不维护旧隐式策略入口。界面和离线试算都只消费保存后的规则，关闭或删除组合规则不会在内核中再次补回。手写规则不受此调整影响。

规则列表从上往下决定优先级，首条实际命中的规则决定动作；普通条件规则和动态规则使用同一顺序，后续锁定、保留或弃置不覆盖前面的命中。
新智能规则追加在人工规则后方，自动生成的弃置兜底置于智能保护规则之后。跨套装适配是计算配置，不是逐件动作，不截断匹配。
普通独立规则入口同样先执行首条命中规则，未命中才进入评分模块；智能推荐不叠加评分处理页阈值。
原锁、已装备、锁定配装、来源及完整性、整批复算等门禁独立生效，冲突时不派发；顺序不是绕过这些门禁的许可。
旧推荐方案需重新生成并保存，明确切换到全角色范围；人工规则不会被删除，旧的常用角色及配装来源设置不再作为计算输入。

推荐冻结账号代次、完整库存、角色/权重、配装槽位、静态资料、已保存规则及套装匹配。生成、采用和实际保存均核对相关输入；
权重、来源或规则变化要求重算。关闭窗口取消后台任务，等任务释放资源后退场；账号切换撤销旧任务。
修改规则后只撤销已失效的智能建议草稿，不撤销手动修改；重新采用建议不会沿用上一轮未包含的装备目标。
打开或刷新仓库后，先显示库存，再通过独立后台任务自动补齐仓库分；无需生成规则或计算弃置建议。任务固定页面快照、账号代次、评分资料和配置；新刷新、账号切换或关闭使旧评分失效。评分失败保留库存并显示原因，下次刷新重试；没有库存或有效样本时明确显示暂无，不把未知写成零分。保存规则后可刷新评分，正式建议产生的同源分数也可立即展示。

## 默认规则口径

- 空幕评估全部有正式评分和合法套装蓝图的角色，按角色、套装、主属性保留候选。已确认跨套装用途进入同一匹配流程。
- 仓库分评估高分质量样本，不取当前已装备角色均分，也不再为分数求解配装。空幕取全部有已确认评分用途的库存中最高的 25 件，不足时按实际件数平均。
  每个角色的蓝图按形状数量组合去重后等权平均，汇总全角色各形状需求，再按通常四舍五入取整。驱动各形状独立按最高适配得分率取够对应数量，同一 UID 不重复计入。
  空幕与驱动分别按评分 ÷（格数 × 10）求平均；总分为空幕平均得分率 × 150 ＋驱动平均得分率 × 200，沿用 350 制。缺任一类有效样本时总分保持未知，显示实际样本数和形状缺口。
  数量抽样只进行计数、排序、平均，复用本次冻结评分与蓝图；这些高分样本不承诺能同时配给所有角色，弃置安全仍由独立全角色配装检查保证。
- 驱动对全部角色复用现有合法蓝图、公共评分与角色优先分配。蓝图按形状数量组合去重，平均形状需求只辅助储备，不把同一角色各张可选蓝图的需求直接累加。整批校验保留可行配装见证。
- 未来储备偏好与实际角色模型分开：生命、防御、治疗和输出方向按同类主副属性协同。
  双暴是两个实际副词条，不能把暴击主属性计为缺失的暴击副词条；治疗及元素伤害主属性不伪造为副属性。
- 推测的元素主属性用途须与已审查的套装元素一致，或有当前角色的明确套装与主属性适配；
  光套＋咒伤等已确认跨套装用途仍通过同一角色适配输入生效，不推广成任意套装配任意元素。
  未确认角色时，治疗方向只允许相应生命／治疗或防御套装；不凭有效副属性数量为暗套＋灵伤等组合补造用途。
  未编辑的自动四词条保护规则也执行跨元素用途校验，不允许经最终规则仲裁绕过；通用环合、倾陷、生命和防御主属性不按元素冲突处理。
  用户手写或明确编辑的规则，以及单列的已确认光套组合规则，保留各自明确的保护范围。
  未来储备不纳入已标记弃置的装备；只有当前用途、已装备、配装见证或明确保留规则才能建议恢复正常。
- 双暴＋伤害增加＋攻击力%或环合强度的空幕及驱动，默认生成明确保留规则，不受同类数量、候选排名或评级限制。
  当前没有充分证据判断主属性严重错误时仍保留；不会仅因常用角色暂时用不上而推荐弃置。
- 全套装空幕的倾陷主属性＋双暴＋增伤＋倾陷，以及生命／防御主属性＋双暴＋增伤＋对应百分比副属性同样明确保护。
  驱动另保护双暴＋增伤＋倾陷／生命%／防御%，以及双暴＋攻击力%＋环合／倾陷。
  每种四词条组合独立生成可编辑规则，四条都须是实际存在的正数副属性，不用主属性充当副属性。
- 明确要求的强势套装任意主属性＋双暴＋增伤／环合／攻击力%，以及相应输出、生命、防御、治疗组合直接保留，
  不受额外候选数量截断。其余按套装／主属性（驱动按形状）、用途及有效副属性签名分桶。
- 音速蓝刺猬（正式身份 Suit11）另有五条独立辅助保留规则：不限主属性，实际副属性同时具有暴击率、暴击伤害、通用增伤，
  再有攻击力%、防御力%、生命值%、环合或倾陷之一，四条均须为正数。各品质沿用规则范围，不受预算或重复备用压缩。
  辅助用途不套用元素主属性冲突筛选；仍遵守可编辑规则的首条命中顺序。已有账号需重新生成并保存才能加入新规则，不暗改已保存列表。
- 非支配筛选只对同资格、同签名的候选比较。驱动还覆盖已有合法蓝图中的单组最大形状重复数。
  每个候选组默认保留两件，可在动态规则编辑；前沿不足数量时允许较低质量副本补足。
- 未来用途规则默认目标保留总量为 1000 件，0 表示不限；这是保护优先的目标，不是强制弃置配额。
  已锁定、已装备、可行配装、达到所选保留评级、规则选出的锁定首选、明确组合、手写保护和不能确认弃置的物品先占预算；原已弃置且没有恢复理由的待核对项不占保留数量。
  超出目标时，仅未命中上述保护的当前用途备用候选按同套装/主属性或驱动形状、实际适配范围分组，分别覆盖暴击率/暴击伤害/增伤组合
  与攻击、生命、防御、环合、倾陷、急速方向，先保留各取向最高评分代表，再按归一分数从低到高压缩重复备用。
  同一件可覆盖多个取向，不因无关第四词条变化就额外保留；主词条不充当暴击副词条。不同资格不互相替代。
  基础完美词条和明确储备规则不受该压缩影响，未来用途分桶和组内数量规则仍沿用原契约。
  剩余名额按五种未来用途轮流选择，组内按公共评分面积归一值排序，每个储备组按数量及已知形状重复需求整组纳入或跳过。
  必要保护超过目标时允许超额，预览记录目标、必要保护、额外未来储备及预算未覆盖的组数。
- 驱动评级额外保留可关闭或选现有 D～ACE 任一最低评级，默认 SSS。依据全部适配角色中的最高有效评分，
  使用既有面积归一化评级判定，达到门槛的驱动全部受数量硬保护，重复件也不能因数量目标被压缩。该规则只作用于驱动；与其他规则冲突仍遵守首条命中优先，不调整用户规则顺序。
- 当前用途桶冠军达到现有 SSS 线或属于可行配装见证时，启用规则选择锁定动作则建议锁定；这些锁定首选也不能被数量压缩撤销。未来假设本身只产生保留候选。
  现有锁定单独标记，即使模型认为冗余也不自动解锁。
- 增加未来储备不得扩大弃置集合。没有已确认用途／替代关系、模型缺项或求解未完成时保留待判断。

## 分层与复用

`src/domain/equipment/warehouse_recommendation.py` 消费冻结纯值并给出建议；
`src/services/inventory/warehouse_recommendation.py` 在调用方提供的离线账号副本上编排公共评分、蓝图和分配内核；
`tools/warehouse_recommendation_trial.py` 读取离线账号中已保存的同一规则方案，冻结静态输入、检查来源未变并导出结果；
`tools/warehouse_recommendation_report.py` 生成可筛选的本地报告。推荐本身不连接游戏；UI 将勾选建议送入仓库待保存列表。

试算建立全部可计算角色的正向及反向顺序、逐个角色，以及启用的已保存配装偏好最新版本的冻结方案；正向方案复用本次已建立的基线，不重复求解。
按最终采用动作计算移除集合，包含原已弃置且未采用恢复的物品。逐角色检查有效性、原有空幕是否仍可配齐及基础评分不下降，不用总分提升抵消个别角色损失。
整份已验证方案的装备均仍保留时，复用其可行性证据；只有受移除影响的范围才重新求解。证据记录明确区分原方案保留、复算方案保留及本轮复算。
发现损失时按需撤回相关装备的自动弃置，再验证；分配重排导致仅补本角色不足时，补回受影响范围内原方案所需装备。最多四次补回后仍有损失则禁止采用。
明确人工弃置规则发生冲突时不静默覆盖，提示调整规则；取消、超时、证据缺失或求解失败也不能生成成功证明。
校验后的必要保留可超过目标数量，预览显示补回数量和实际保留总量。部分采用时必须继续保留证明所需装备；取消必要恢复后，采用和正式派发入口都会阻止相关弃置。
原库存已经缺少某套空幕时明确提示原有缺口，不把它伪装成配齐，也不允许扩大已知缺口。

评分、批量评级及无通用属性限制的角色优先求解复用正式 Rust 核心；该求解器具有保守上界剪枝。Python 只编排冻结请求、规则和补回证据，不另写评分公式。
已保存档案有通用属性上下限或旧暴击阈值时仍使用支持该约束的既有内核，不删除约束来走快路径；Rust 求解失败不静默降级。
报告分别记录原始已装备分数、全仓方案、移除后证据、原游戏状态、模型建议和实际新增动作数量。
搜索有界且角色优先，不宣称全局最优、任意顺序或未来角色均有足量装备，也不把基础评分不降解释为所有战斗条件下伤害不降。


## 验证边界

现有专项覆盖算法保护、批量移除、来源快照、输入变更、配置保存、取消和预览草稿；真实仓库副本用于离线试算。
合成专项覆盖发行全部套装的明确空幕组合、含两格形状的七类优秀驱动大量重复、空库存、装备不足、少角色和丰富库存；
整批移除使用公共评分与分配内核复算，不用另一套简化公式代替生产评分。合成蓝图用于验证库存分配边界，不等于全角色真实蓝图验收。
尚未以真实游戏派发验收，也未宣称任意未来角色或任意角色优先级下全局最优。实际约束无法由正式见证求解覆盖时，不推荐弃置。
